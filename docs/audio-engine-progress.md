- Phase C: Added the default-microphone capture worker in `src/microphone_capture.rs`. Capture starts only after both helper channels connect and the versioned handshake succeeds. ## Decisions made

- Desktop local encoding resolves an explicit absolute `ORION_RECORDING_FFMPEG_PATH`, uses `ffmpeg` from `PATH` in development, and expects the Phase G packaged binary under `resources/bin`. No third-party npm FFmpeg binary package was added; licensing and signed binary assembly remain one Phase G packaging concern.
- Phase H is limited to transcript-derived summaries, decisions, and action items. Third-party product integrations/connectors are excluded by confirmed product decision.
- Implicit and explicit auth teardown share the same recording barrier, but implicit loss is best-effort: it must publish the authoritative auth failure even when recording finalization fails. Cached-token access and recording-start fencing apply for the full serialized teardown window.
- Backend orphan reconciliation uses 250-session `ANY(uuid[])` batches against the recording primary key. A spool is retained only when both its database session UUID and owning user UUID match a nonterminal row; an inventory or database error fails closed and deletes nothing from the affected batch.
- Desktop local-spool cleanup uses a stable random owner UUID stored under Electron `userData`. This prevents one Orion installation from deleting another machine's in-progress staging directory when the selected recordings folder is synchronized or shared, while still allowing immediate cleanup after a crash on the owning installation.
- Server-mode audio retention must remain available independently of AssemblyAI transcript availability. A quota/provider failure may stop provider forwarding and publish transcript `unavailable`, but it must not stop authenticated frame admission, acknowledgement, or backend disk spooling.
- Transport availability and transcript availability are separate main-process states. A live authenticated socket may remain healthy for server storage and finalization after AssemblyAI becomes unavailable; only a socket/reconnect failure disposes that transport.
- The backend manifest is both the last B2 upload and the local durable cloud-commit receipt. It is atomically committed locally only after B2 acknowledges it, retained until database completion, and validated against the session and artifact contract before a finalization retry trusts it.
- Native resampling remains on pinned Rubato FFT resampling, now behind one mono streaming boundary. Startup delay is trimmed, final filter delay is drained without padding retained output, and capture discontinuities reset the filter rather than blending samples across a gap.
- VAD uses the pinned MIT-licensed `webrtc-vad` implementation independently of the broader WebRTC Audio Processing pipeline. Silence remains continuous timestamped PCM; VAD is metadata only and never gates AssemblyAI transport, reconnect replay, or recording storage.
- WebRTC Audio Processing uses pinned BSD-3-Clause Sonora 0.2, a pure-Rust WebRTC M145 port with AEC3, NS, and AGC2 plus native Windows x64 and macOS ARM64 coverage. This avoids shipping a separately built C++/Meson runtime. Its declared minimum raises the helper MSRV from Rust 1.85 to 1.91; both supported development machines currently use Rust 1.98. Source-local AGC is capped at 20 dB for microphone and 12 dB for system audio, changes at no more than 3 dB/s, and refuses to raise output noise beyond -50 dBFS. System noise suppression defaults off to preserve already-processed meeting playback; microphone suppression defaults moderate.
- Microphone AEC3 consumes raw pre-AGC system PCM through a non-blocking 64-block channel rather than sharing DSP state or collapsing the two captured sources. The system worker marks a discontinuity after reference-channel overflow; the microphone worker resets AEC on discontinuity, rejects references more than 500 ms stale, allows at most 20 ms timestamp lead, and falls back to microphone NS/AGC without changing session health when no valid reference exists.
- DSP diagnostic toggles are helper-global and atomic: VAD and AGC apply to both captured sources, while NS and AEC apply only to microphone processing. This keeps the diagnostic contract small, avoids callback locks, and prevents unsupported system-source suppression/echo settings from appearing effective. Changes take effect at the next 60 ms frame boundary and preserve already-buffered VAD output ordering.
- DSP telemetry contains scalar processing facts only, never PCM, transcript text, device labels, or other speech-derived content. `configuration` reports requested atomic settings while per-source activation fields report the most recently applied worker state, making frame-boundary propagation observable without blocking capture.
- DSP toggles are session-scoped diagnostics, not persisted preferences. Only the authenticated dashboard renderer may read or change them; each new recording starts with production defaults, while an automatic helper replacement restores the current session's toggles before recovery. This prevents a forgotten diagnostic override from silently weakening later recordings.
- Phase F closes through its explicit UI-guidance branch for residual echo. Native AEC3 remains the primary mitigation; Orion does not heuristically discard similar cross-source transcript text because identical or overlapping speech can be genuine. The dashboard transcript warning states the concrete risk and headphone mitigation without claiming notes or future AI output are unaffected.
- Graceful app quit allows 15 seconds for renderer draft fencing, helper drain, and backend finalization. This bounds shutdown latency while covering normal completion; deadline/failure disposes capture immediately and delegates durable closure to the existing backend janitor rather than leaving Electron or the helper alive indefinitely.
- Startup discovery never auto-finalizes or revives a non-terminal backend recording. The row may represent this installation after a crash or another device still recording, so discovery only surfaces authenticated recovery state. Closing that row requires an explicit recovery action; subsequent Resume still creates a new client session ID.
- Explicit recovery requests `cloud` finalization because only the backend can inspect and commit a surviving server spool; the finalizer truthfully records `none` when no spool exists, covering crashed local/no-retention sessions without inventing retained audio. The 30-minute desktop request deadline remains bounded while allowing disk encoding and upload to finish.
- Release assembly never discovers FFmpeg from `PATH` and never trusts runtime executable overrides. Packaging requires `ORION_PACKAGED_FFMPEG_PATH` and `ORION_PACKAGED_FFMPEG_LICENSE_PATH`; an optional absolute `ORION_PACKAGED_AUDIO_ENGINE_PATH` supports externally signed/reproducible helper input, otherwise the hook builds `cargo build --release --locked`. Fixed resource names let full-app updates replace helper and encoder atomically with the application version.
- Release packaging is intentionally deferred, not passed. Development requires no bundled FFmpeg: live transcription and no-retention mode do not use it, server retention uses backend FFmpeg, and desktop local retention resolves an installed FFmpeg or explicit development path. The later release goal owns the LGPL/GPL distribution decision, signing identities, notarization, and update artifact verification.

- The Phase A skeleton uses the fixture's existing 250 ms startup and 600 ms finalization delays to preserve UI timing until real helper/backend events replace timers in later phases.
- A completed recording is discarded as manager state before a new `starting` snapshot is created. This treats resume as a new session identity instead of an illegal transition from `complete`, matching the final plan.
- The IPC controller treats live events as newer than the initial snapshot request and overlays those event objects during hydration. Source-mute methods fail explicitly until their new engine-control IPC is introduced instead of pretending a mute succeeded.
- Per the user's Phase A amendment, main-owned recording is unconditional and the fixture is no longer a runtime compatibility requirement. The old renderer-publication IPC names remain inert to preserve channel-name stability without permitting a second author.
- Phase D repository transitions are single conditional SQL statements rather than read-then-write transactions. This makes invalid or concurrent state changes fail atomically, keeps user ownership in every session-scoped operation, and preserves `last_activity_at` as the last real heartbeat when the janitor later marks a row abandoned.
- Phase D uses one idempotent REST transition resource rather than separate action endpoints: `PATCH /api/recordings/:sessionID` accepts a target status and conditionally invokes the corresponding repository transition. HTTP retries are idempotent only when the stored target state (and, for completion, `audio_stored`) exactly matches; stale, skipped, or reversed transitions return a stable conflict. Heartbeats are not exposed over HTTP because the plan assigns them to the audio WebSocket.
- Phase D stale-session timing defaults to a 90-second heartbeat timeout and a 30-second sweep. This leaves margin over the existing 70-second WebSocket read timeout while bounding worst-case stale-session release to roughly two minutes; deployments may tune both durations, but startup rejects unsafe/out-of-range values and a sweep interval longer than the heartbeat timeout.
- Phase D carries the recording-row UUID in the transcription socket's existing authenticated first message as `recording_session_id`, rather than in the URL. This keeps the identifier out of request URLs and access logs, preserves the existing route and generic WebSocket handshake, and gives the backend the authenticated user identity before performing the ownership-scoped lookup.
- Phase D refreshes the session heartbeat immediately on admission and every 25 seconds thereafter, with each database operation bounded to five seconds. The cadence shares the existing WebSocket keepalive interval, remains comfortably below the 90-second abandonment timeout, and avoids a write per audio frame. All three database non-terminal states (`starting`, `recording`, and `finalizing`) are admitted exactly as the plan defines; terminal states receive the same unavailable response as an unowned or unknown row.
- Phase D reuses one versioned source-aware binary layout on both native IPC and desktop-to-backend legs. Its sample-format field is the codec tag; version 1 remains PCM16 as planned, while the final PCM-versus-Opus decision stays open until end-to-end measurements exist. The backend preserves sequence/timestamp metadata for later event reconciliation and routes only the PCM portion to AssemblyAI.
- With separate microphone and system frames, transcription quota is measured as the greater cumulative source duration, matching the prior interleaved stream's elapsed-time accounting. Summing both sources would incorrectly bill two seconds for one second of simultaneous capture.
- The selected hosted path is a direct AssemblyAI integration, not a generic cloud-provider interface. Orion's authenticated source-aware WebSocket and normalized transcript-event contract remain application-owned boundaries so a future local engine can be designed separately without making unused multi-provider machinery a Phase D requirement.
- Storage intent is carried in the authenticated transcription handshake as `audio_storage`. Missing intent temporarily maps to `none`, keeping the existing desktop server path operational until backend Opus finalization can replace it atomically; the desktop will start sending `server` only when the backend can seal, encode, upload, and clean the spool.
- Backend retained-audio encoding uses FFmpeg's libopus encoder instead of adding an immature in-process codec dependency. PCM is piped record-by-record from disk into the encoder, while only bounded frame/hash buffers are held in memory. The backend validates FFmpeg availability during startup so server-retention capability cannot fail silently after capture.
- Speaker diarization is explicitly excluded. `source: mic|system` continues to identify the reliable capture origin, and word timings remain available; neither the planned transcript event nor the later segment migration will add speaker IDs, names, confidence, or correction state.
- Orion's backend transcript wire event uses snake_case JSON and renderer-compatible millisecond `created_at` plus second-based transcript/word timings. `session_id` is the desktop client session ID, not the database row UUID; the socket is already bound to the database row during admission.
