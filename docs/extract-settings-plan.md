# Extract settings — implementation plan

## Goal

Add the initial backend persistence and desktop settings UI for configurable extract fields. A field contains a name, an extraction prompt, whether it expects one or multiple insights, and the meetings it will eventually apply to.

The meeting target dropdown contains:

- **All meetings**
- Every active folder owned by the signed-in user

This phase stores configuration only. It does not run prompts, process transcripts, generate insights, backfill meetings, or display extracted results.

## Data model

Add `public.account_extract_fields` through a Supabase migration and mirror it in `supabase/schema.sql`.

| Column | Type | Purpose |
|---|---|---|
| `id` | `uuid` | Primary key, generated by PostgreSQL |
| `account_id` | `uuid` | Owning account; references `accounts(id)` with cascade delete |
| `name` | `text` | User-facing field name |
| `prompt` | `text` | Instructions saved for future extraction |
| `insight_cardinality` | `text` | `single` or `multiple` |
| `folder_id` | `uuid null` | `NULL` means all meetings; otherwise targets one folder |
| `created_at` | `timestamptz` | Creation time |
| `updated_at` | `timestamptz` | Last modification time |

Use a composite foreign key from `(folder_id, account_id)` to `folders(id, user_id)` so a field cannot reference another user's folder. The authenticated user's current ID is also the account ID in Orion's current one-user-per-account model.

Database constraints:

- Trimmed `name` must be non-empty and no longer than 100 characters.
- Trimmed `prompt` must be non-empty and no longer than 4,000 characters.
- `insight_cardinality` must be `single` or `multiple`.
- Add an index on `(account_id, created_at, id)` for stable listing.
- Prevent duplicate field names per account case-insensitively with a unique expression index on `lower(btrim(name))`.

Enable and force RLS. Revoke access from `PUBLIC`, `anon`, and `authenticated`; grant only the required `SELECT`, `INSERT`, `UPDATE`, and `DELETE` permissions to `orion_backend`, with account-scoped policies matching the backend trust model already used by account vocabulary.

Folders are soft-deleted, so their foreign keys remain valid. If a targeted folder is later soft-deleted, preserve the extract field but report its target as unavailable. Never reinterpret it as **All meetings**, because that would silently broaden its future scope.

## Backend

### Model and repository

Add:

- `backend/internal/models/extract_field.go`
- `backend/internal/repository/extract_field.go`

Model shape:

```go
type ExtractField struct {
    ID                 string    `json:"id"`
    AccountID          string    `json:"account_id"`
    Name               string    `json:"name"`
    Prompt             string    `json:"prompt"`
    InsightCardinality string    `json:"insight_cardinality"`
    FolderID           *string   `json:"folder_id"`
    FolderName         *string   `json:"folder_name,omitempty"`
    ScopeAvailable     bool      `json:"scope_available"`
    CreatedAt          time.Time `json:"created_at"`
    UpdatedAt          time.Time `json:"updated_at"`
}
```

Repository operations:

- `List(ctx, accountID)` — list all fields in stable creation order and left-join active folders for `folder_name` and `scope_available`.
- `Create(ctx, accountID, input)` — insert and return the field.
- `Update(ctx, accountID, fieldID, input)` — update only a field owned by the account.
- `Delete(ctx, accountID, fieldID)` — delete only a field owned by the account.

All mutations must include `account_id` in their predicate. Do not accept an account ID from the request body.

### HTTP API

Add `backend/internal/handlers/extract_fields.go`, construct it in `backend/cmd/api/main.go`, and register authenticated routes:

```text
GET    /api/extract-fields
POST   /api/extract-fields
PATCH  /api/extract-fields/:fieldID
DELETE /api/extract-fields/:fieldID
```

Request body for create and update:

```json
{
  "name": "Pain points",
  "prompt": "What pain points does the prospect face?",
  "insight_cardinality": "multiple",
  "folder_id": null
}
```

`folder_id: null` means **All meetings**. A UUID means the selected folder.

Response shapes:

```json
{ "fields": [] }
```

```json
{ "field": {} }
```

Status behavior:

- `GET`: `200`, including an empty array when no fields exist.
- `POST`: `201` on success.
- `PATCH`: `200` on success; `404` when the field is not owned by the caller.
- `DELETE`: `204` on success; `404` when the field is not owned by the caller.
- Invalid input or a missing/inaccessible folder: `400` with a stable error code.
- Duplicate case-insensitive name: `409` with a stable `extract_field_name_conflict` code.

The handler must trim names and prompts, validate lengths and cardinality, and call `FolderRepository.ExistsForUser` whenever `folder_id` is non-null. Database constraints remain the final enforcement layer.

## Desktop settings UI

### Client and types

Add:

- `desktop/src/types/extract-field.ts`
- `desktop/src/lib/extract-fields-client.ts`

The client should use `authenticatedFetch`, map API snake_case values to renderer camelCase, and expose:

```ts
listExtractFields(): Promise<ExtractField[]>
createExtractField(input: ExtractFieldInput): Promise<ExtractField>
updateExtractField(id: string, input: ExtractFieldInput): Promise<ExtractField>
deleteExtractField(id: string): Promise<void>
```

Reuse `listFolders()` from `desktop/src/lib/folders-client.ts` for dropdown options rather than adding a new folders endpoint.

### Extracts page

Update the existing Extracts placeholder in `desktop/src/components/DashboardSettingsPage.tsx`.

Page behavior:

1. Load extract fields and folders when the Extracts section becomes active.
2. Retain the current **Fields** heading and description.
3. Render each saved field as a bordered settings row showing its name, prompt, `Single`/`Multiple`, and `All meetings` or folder name.
4. Keep **Add new field** as the final row/button.
5. Provide edit and delete actions for existing fields.
6. Show loading, empty, submission, and inline error states without replacing saved content.
7. If a referenced folder is unavailable, show **Folder unavailable** and require the user to edit the scope; do not display it as **All meetings**.

### Add/edit dialog

Build the dialog with the existing `Dialog`, `Input`, `Select`, and `Button` primitives. Use a styled native `textarea` for the prompt unless a reusable textarea primitive is added.

Fields:

- **Name** — placeholder `e.g. Pain Points`
- **Prompt** — placeholder `e.g. What pain points does the prospect face?`
- **Number of insights** — `Single` or `Multiple`, default `Multiple`
- **Apply to meetings in** — `All meetings` followed by active folders, default `All meetings`

Interaction requirements:

- Disable **Create**/**Save** until all required values are valid.
- Disable dialog controls while the mutation is in flight to prevent duplicate submissions.
- On success, update the local list from the returned field and close the dialog.
- On failure, keep the dialog open and show the API error.
- Reset draft state only after a successful create or an explicit cancel.
- Use the same dialog for editing, prefilled with the selected field.
- Confirm deletion before sending the request; remove the row only after success.

## Delivery phases

### Phase 1 — Database

- Add the migration, table, constraints, indexes, grants, and RLS policies.
- Update `supabase/schema.sql` to remain the canonical schema snapshot.

### Phase 2 — Backend CRUD

- Add model, repository, validation, handler, and authenticated routes.
- Verify ownership and folder validation on every mutation.

### Phase 3 — Desktop client and UI

- Add types and API client.
- Replace the placeholder with loading/list/error states.
- Add create/edit dialog and deletion flow.
- Populate meeting scope from the existing folder endpoint.

## Verification

### Database and backend

- `go test ./...` and `go vet ./...` pass from `backend`.
- An unauthenticated request is rejected.
- A user can list, create, edit, and delete their own fields.
- A user cannot read or mutate another account's fields.
- A user cannot select another user's folder or a soft-deleted folder.
- `folder_id: null` round-trips as **All meetings**.
- Invalid cardinality, blank/oversized values, and duplicate names return the expected status and code.
- Direct database writes cannot bypass ownership, field-length, cardinality, or folder-ownership constraints.

### Desktop

- `npm run lint` passes from `desktop`.
- `npx tsc --noEmit` passes from `desktop`.
- Empty state shows **Add new field**.
- The dialog matches the supplied layout and contains current folders beneath **All meetings**.
- Create, edit, delete, refresh, API-error, and unavailable-folder states behave correctly.
- Saved settings persist after navigating away and reopening Extracts.

## Explicitly deferred

- Running extraction prompts against transcripts
- Queue or worker changes
- AI provider request/response schemas
- Associating results with notes or meetings
- Applying folder scope during processing
- Historical meeting backfills
- Displaying extracted insights outside the settings page
